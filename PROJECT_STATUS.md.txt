## Important Decisions

### Identity

* Registration requires only FirstName, LastName, Email and Password; PhoneNumber is optional. Address, national ID, birth date and gender are not registration requirements.
* Normalized email is unique; optional phone uses international +countrycode format and a filtered unique index.
* Public registration assigns Customer only and creates an active account. OTP/contact verification is deferred.
* PasswordHasher uses 600,000 iterations with rehash-on-login support. Passwords are 12–128 characters with upper/lowercase, digit and symbol rules.
* JWT signing keys come only from secure configuration/environment; there is no checked-in key or development fallback.
* Access tokens default to 10 minutes; refresh sessions have an absolute 30-day lifetime.
* Refresh secrets are 256-bit random values; only SHA-256 hashes are persisted. Consumed-token replay revokes the whole session.
* Authentication/rotation/logout/status operations serialize relevant user changes with SQL row locks and commit audit with business state.
* Each authenticated request checks persisted active user/session state and reloads role/permission assignments for immediate revocation.
* Role assignments invalidate existing access tokens; permission changes are enforced from current persisted assignments.
* Initial administrator creation is an explicit one-time command using secure configuration, guarded by a SQL application lock. No bootstrap endpoint exists.
* Shared ApiResponse moved to BuildingBlocks Abstractions for module reuse. Foundation's existing exception pipeline accepts safe application errors; the Foundation was not redesigned.
* No OTP/SMS, RabbitMQ, Redis or Phase 3+ business functionality was added.

### Inventory

Cart does not reserve stock.

Inventory is deducted only after successful payment.

Stock deduction must be atomic/concurrency-safe.

### Payment

Payment verification is server-side.

Payment operations must be idempotent.

### Wallet

Wallet uses a ledger.

Refunds are idempotent.

### Refund

If payment succeeds but inventory is unavailable, refund processing is asynchronous and delayed.

Do not block a request/thread for one hour.

### Messaging

Important integration events use Transactional Outbox before RabbitMQ publication.

### Redis

Redis is not the source of truth for financial or inventory data.
